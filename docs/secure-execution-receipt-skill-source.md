# Foxlin Industries — Secure execution receipt source integration

Unreleased source contract. Exact source-bound C7 command and independent review receipts govern qualification; this guide does not grant packet or production acceptance. Current SDK version0.1.2-beta.1/0.1.2b1 remains unreleased. No package publication or version change is authorized.

The bounded operation is the current canonical group administrative metadata read. It requires the approved immutable Skill/adapter, current installation/enablement, genuine Human consent, active approved Agent lineage and finite reserved quota. The operation is not a shell, plugin loader, business-write adapter or receipt-based login.

The .NET source API is Foxlin.Aegir.Auth.Delegation.AegirSecureExecutionSkillApiClient. Construct it with an HTTPS root URI, the current Agent key, its own installed ags2_ delegation reference and a separately trusted AegirReceiptTrustedServiceKey. The optional certificate pin is restricted to explicit loopback testing. Redirects, proxies and cookies are disabled. Requests and responses are bounded, with a30-second deadline and no automatic retry.

Create one AegirSecureExecutionRequest with a stable OperationId and known SkillKey/Version/ManifestDigest/AdapterDigest/ResourceAlias/TenantId/AgentId/RootGrantId/ExpectedGrantId. ExecuteAsync returns protected metadata only for a newly committed read. ReconcileAsync uses the SAME original request/ID and returns the original retained receipt, without private metadata. Exceptions preserve OperationId and require explicit reconciliation; a failed connection or missing row is never Abort and must not cause an automatic new ID.

The real API is POST /v1/skills/v2/secure-execution. Credentials are X-Aegir-Agent-Key and X-Aegir-Delegation; keep them out of files/logs/examples. Its exact request keys are action,operationId,skillKey,skillVersion,manifestDigest,adapterDigest,resourcePolicy,resourceAlias,scope,operation. resourcePolicy is group.administration.metadata.read; scope is security:read; operation is group.administration.metadata.execute-with-receipt. action is execute/status/verify. Raw verify additionally carries receipt. The typed source client offers ExecuteAsync and ReconcileAsync; it does not invent a typed online VerifyAsync operation.

An artifact contains claims and signature. All37 claims are signed in fixed field order with domain Foxlin.Aegir/secure-execution-receipt/v1; domain and each strict-ASCII/UTF8 value have Int32 little-endian byte-length prefixes. The genuine algorithm is ML-DSA-65. SHA-256/HMAC commitments are not substitute signatures. The public key is not trusted because the artifact names it. Obtain and pin public key bytes, service principal/purpose and lifecycle metadata through a separately approved trust process; production public-key distribution is not qualified here.

AegirSecureExecutionReceiptVerifier validates the supported contract, canonical bytes, actual signature and supplied operation/tenant/Agent/root/grant/resource context. Its success is artifact math under the pinned key/context, not current authority, independent SQL commitment observation, client delivery or external effects. Metadata is authenticated by HTTPS; the public verifier cannot recompute the server-private result HMAC. The online server additionally matches the artifact to independently retained original operation truth. A differently signed artifact or unknown operation cannot replace that truth.

Committed artifacts remain immutable after authorization changes. Old receipts are not bearer credentials. Service key lifecycle verification is valid-at-signing-time under separately trusted lifecycle facts; this does not establish independent trusted time or protect against a compromised signer forging claims. Current server authority, retained SQL/witness truth and client-delivery evidence are separate. Existing encrypted PKCS8/configuration-KEK custody is not HSM custody. Unknown or unavailable trust remains quarantined rather than re-signed or inferred aborted.
