# Authentication integration Skill — Foxlin Industries

Unreleased source-only C3 adds one API operation: `POST /v1/skills/v2/authentication-integration`, `application.authentication.integration.inspect`, with the new `application.authentication.integration.read` resource. This inspects the selected application's actual executing API host return-URI configuration prerequisites. It neither authenticates a Human nor starts or certifies a handoff. No password, factor, token, URL, provider credential or signing-key value is returned. Native mobile, factor recovery and passkey-only login remain unavailable through this Skill.

The organization/group profile requires the canonical current original Human and administrative source, original scoped session, current mapped application, effective membership and **read policy on the exact selected group**, application license, approved immutable Skill/version/actual Auth artifact, current organizational enablement, enabled C2 installation, current enterprise policy, exact Agent chain and finite reserved uses. Another group's read permission never substitutes. Personal scope is unsupported. `resourceId` is the application ID; it is distinct from `groupId`. Installation alone grants no execution authority. Lost original authority requires fresh consent; reinstall uses a fresh installation ID.

The approved built-in ID is `aegir.authentication.integration-inspection`, adapter `foxlin.builtin.authentication-integration.v1`, profile `aegir.c3.builtin-authentication-inspection/v1`, with input/output identities `aegir.skill.authentication-inspection-input/v1` and `aegir.skill.authentication-inspection-output/v1`. Use the existing registry review/approval and C2 installed root/child lifecycle with these exact reviewed manifest pins. Descriptions are inert. Actual Auth PE bytes cover the substantive configuration reader, classifier and pure executor. API glue cannot supply arbitrary mode support.

The strict request has `action` (`execute` or `status`), durable `operationId`, `skillKey`, `skillVersion`, `manifestDigest`, `adapterDigest`, `resourcePolicy`, opaque `resourceAlias`, `scope` (`security:read`), and exact `operation`. See [schemas](contracts/e2-c3/openapi.json). HTTP response schema `aegir.authentication-skill.execution/v1` wraps `result`. A successful inspection returns only output schema, opaque alias, exact operation, `configurationAuthority=executing-api-host`, `returnUriConfiguration`, bounded inspected/usable entry counts and fixed false `ceremonyExecuted`/`authenticationEstablished`. At most16 configured entries are classified; excess is `inspection-limit-exceeded`, not an assertion that the handoff engine cannot work. Missing and invalid entries are observations, never authority or health certification. Configuration can change immediately after observation. Canonical alias projections, quota accounting and audit may persist; authentication and application business state are not mutated.

The .NET source consumer `AegirAuthenticationSkillApiClient` accepts only explicit HTTPS API origin, current Agent key and `ags2_` reference. `AuthenticationInspectionRequest` fixes expected grant and original durable identity. `InspectAsync` and `ReconcileAsync` use the same original request; no retries, redirects, cookies, proxies, Human fallback or secret replay. Retain operation context securely. Exact duplicate execution returns no second private result. Explicit status returns nonsecret `CommittedRead` and server-protected commitment, never the original private output; the HMAC is not a public signature. Unknown, interrupted or unverifiable outcomes require reconciliation, never inferred Abort. Current authority loss refuses new reads; completed observations cannot be retroactively undone.

.NET is the only new typed source binding. Node/TypeScript, Python, Java and Go have the raw HTTP contract only. Existing typed `AegirSkillMcpClient` and HTTP MCP `skill_metadata_execute_v1` remain audit metadata only and reject this resource. No new MCP or stdio tool: HTTP registry14, stdio12. No package version bump or publication. Human Eyes and external deployment remain Deferred — Not Accepted; production release is unauthorized. Exact C3 source/evidence receipts determine bounded acceptance.

The first profile requires ASCII application identifiers without colon. Existing registration naming/ownership semantics and handoff behavior are preserved. This bounds materialization, not scan cost, and imposes no application-creation quota. Cancellation/timeouts remain operative; no production-scale claim is made. Nested or nonnumeric callback-array shape refuses without entry counts, preventing a foreign `parent:child` app from being observed through a parent. At most the first17 numeric entries are examined to detect the16-entry inspection limit; this is not arbitrary configuration inventory.
