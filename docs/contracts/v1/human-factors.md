# Human factor contracts — Foxlin Industries

The eight existing `/v1/auth/mfa/*` and `/v1/auth/webauthn/*` operations manage only the authenticated Human owner. Personal users obtain a five-minute purpose-only proof from the Web origin `POST /account/token` with `scope: "mfa:own"`, username/password and, if enrolled, the existing cookie-bound TOTP continuation. This proof carries no developer, application or roles and cannot call unrelated API operations. Existing current Human access/session tokens remain subject to their full canonical checks. Organization attachments do not change factor ownership or create administrative permission.

Enrollment requires fresh proof within five minutes; trusted-device assurance alone cannot enroll factors. Ceremonies bind exact API proof jti or live Web session and User epoch. Revocation/logout/epoch changes cannot be cured by an assertion. `POST /account/logout` revokes the exact signed bearer when supplied, and durably revokes the current cookie session. A new independent login is a separate proof.

WebAuthn uses real Fido2NetLib verification, exact configured RP/origin, required user verification, two-minute one-use challenge, credential ownership, create-only unique IDs and compare-and-swap counters. Backup-eligible/backed-up credentials are refused pending a persisted backup-state lifecycle. Counterless credentials may use zero counters with distinct challenges; no clone detection or hardware claim is made for them. Assertion endpoints return booleans only. A passkey-only factor currently lacks a complete Web login/step-up issuance path; this grant requires an enrolled TOTP factor when MFA is required. Password recovery alone does not bypass the factor gate. Passkey-only issuance and factor-loss recovery remain capability gaps, not elevated platform authority.

TOTP secrets are returned only by initial setup, encrypted at rest, and never returned by status/confirmation/validation. Pending enrollment is five minutes; confirmation activates it and changes User epoch, requiring fresh login. Codes accept one prior/current/next30-second step, monotonically once. Setup cannot overwrite pending or confirmed factors. After pending expiry, a fresh-owner setup call CAS-discards only that exact unconfirmed secret and returns409; authenticate again (epoch changed), then retry setup. Confirmed-factor replacement is not offered by these routes. Interrupted/failed WebAuthn crypto leaves its already-consumed challenge spent.

All responses use no-store. Maximum JSON body65536bytes; unknown outer fields, duplicate keys, query parameters and ambiguous credentials are refused. Errors/audit omit codes, secrets and library exception text. Browser mutations require ASP.NET antiforgery; GET setup does not create a secret. Human Eyes and external deployment remain Deferred — Not Accepted. No package version or publication change.
