# Public Repo Next Pass

This document captures the public-facing improvements that are still best handled in a later pass outside the code-only SDK repo updates.

## GitHub Repository Presentation

The following items should be updated directly in the GitHub repository settings or release workflow:

- repository description
- repository website or docs URL
- repository topics
- first public GitHub Release for `0.1.1-beta-1`

## Public Product Positioning

The GitHub landing experience should answer four questions immediately:

1. what Aegir is
2. who the SDK is for
3. where the docs live
4. which release a developer should start with today

## Docs Expansion Still Worth Doing

The current pass strengthens the landing README and the main integration docs, but a later polish pass would still add value in areas like:

- language-specific sample responses
- troubleshooting checklists
- retry guidance with concrete examples
- richer local MCP troubleshooting guidance
- a dedicated release-notes or upgrade page in the public SDK repo

## Beta-1 Boundary

This note is not a Beta-2 roadmap. It exists to separate GitHub presentation work and future documentation polish from the Beta-1 code and docs improvements already present in this repo.
